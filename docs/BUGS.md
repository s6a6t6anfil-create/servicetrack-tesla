# Журнал фактичних дефектів

## BUG-001 — VIN у нижньому регістрі відхиляється до нормалізації
Пріоритет: Medium. Середовище: Python 3.12, Django 5.2.17, DRF 3.16.1, початковий commit e500ac9.
Кроки: POST /api/vehicles/ з коректними полями та vin=demx0000000000002.
Очікування: 201; VIN збережений у верхньому регістрі. Факт: 400, оскільки RegexValidator виконувався раніше validate_vin.
Доказ: qa/servicetrack/tests/backend-first.txt, test_vehicle_normalizes_lowercase_vin (400 != 201).
Виправлення: нормалізація в to_internal_value до перевірок поля. Регресія: позитивний тест і перевірка дубліката після нормалізації.
Статус: у роботі.

## BUG-002 — картки й фільтр замовлень видно в розділі клієнтів
Пріоритет: Medium. Середовище: Codex IAB, 1280×720, початковий MVP.
Кроки: увійти admin → відкрити «Клієнти».
Очікування: тільки список клієнтів; статистика та прострочення приховані. Факт: застарілі картки 4/3/2 та чекбокс «Прострочені» залишилися.
Доказ: qa/servicetrack/ui/bug-hidden.txt (реальна DOM snapshot).
Причина: CSS display:grid/flex перекрив браузерний стиль hidden.
Виправлення: загальне [hidden]{display:none!important}.
Статус: виправлено; потрібна повторна перевірка браузером.

## BUG-003 — вихід із сесії недоступний у мобільній верстці
Пріоритет: Medium. Середовище: CSS початкового MVP, media max-width:720px.
Кроки: увійти → звузити екран до 390px → знайти «Вийти з облікового запису».
Очікування: дія виходу доступна на всіх екранах. Факт: єдина форма виходу була в .sidebar-bottom із display:none; виявлено переглядом коду.
Доказ: static/app.css в commit e500ac9, правило @media(max-width:720px).
Виправлення: компактний рядок облікового запису й кнопка виходу на вузьких екранах.
Статус: виправлено; потрібна перевірка мобільного viewport.

Примітка до BUG-001: початковий тест містив також неприпустиму літеру O в DEMO. Це дефект тестових даних; їх виправлено на DEMX. Початковий лог не ізолював лише нормалізацію, тому остаточний доказ — повторний тест із валідною нижньорегістровою формою.

## BUG-004 — Unicode та надмірні ID у query спричиняли збій
Пріоритет: Medium. Відтворення: GET /api/orders/?vehicle=² або /api/vehicles/?customer=<100 цифр>. До виправлення: ValueError/OverflowError. Після:400. Причина: isdigit без перевірки ASCII і діапазону SQLite. Виправлено parse_identifier. Регресія test_invalid_identifier_filters_return_400 пройшла;21серверний тест PASS.
