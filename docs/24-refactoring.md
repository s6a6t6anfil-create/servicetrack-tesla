# ПЗ24. Рефакторинг клієнта API

Філатов Олександр Юрійович, КН-42. 29.09.2026.

## Умова і вибір фрагментів

[ПЗ24](https://b.optima-osvita.org/mod/lesson/view.php?id=183984) вимагає знайти 3–5 фрагментів і поліпшити їх структуру без зміни зовнішньої поведінки. Виконано рефакторинг трьох фрагментів у `static/api.js`, техніка **Extract Method** із пояснювальними назвами змінних. Базова версія — `bb273ec`; робоча гілка — `refactor/pz24-api-client`. Усередині уроку помилково №26, номер за навігацією — №24. Окреме прикріплення результатів не потрібне; письмовий опис включено до загального звіту.

До зміни одна компактна функція `requestJSON` одночасно готувала параметри, надсилала запит, перехоплювала транспортні помилки, читала JSON, вибирала повідомлення та керувала завантаженням. Через вкладені однорядкові блоки ці обов’язки було складно переглядати окремо.

## Три виконані зміни

| Фрагмент | До | Після | Користь |
|---|---|---|---|
| 1. Параметри запиту | Об’єкт credentials/headers/CSRF збирався всередині виклику fetch | `buildRequestOptions(options, csrf)` | Окремо видно стандартні параметри та порядок перевизначення заголовків |
| 2. Надсилання й транспортні помилки | Вкладений try/catch серед решти логіки | `fetchResponse(path, options, fetchImpl, csrf)` | Окрема відповідальність: fetch, збереження AbortError, повідомлення при втраті мережі |
| 3. Тіло відповіді й HTTP-помилки | 204, JSON.parse та вибір повідомлень у тій самій функції | `readResponse(response)` | Окремо видно обробку порожньої відповіді, некоректного JSON і статусів; `known` перейменовано на `messagesByStatus` |

Зовнішній експорт `requestJSON` та його аргументи залишені. Допоміжні функції внутрішні; імпорти інших модулів міняти не потрібно. Координатор тепер читається послідовно:

```javascript
onBusy(true);
try {
  const response = await fetchResponse(path, options, fetchImpl, csrf);
  return await readResponse(response);
} finally {
  onBusy(false);
}
```

`await readResponse` навмисно лишається всередині try: індикатор має згаснути після читання тіла, а не лише після отримання заголовків. Збережено точні повідомлення, CSRF, same-origin, можливість перевизначення options/headers, 204 → null та повернення AbortError.

## Перевірка збереження поведінки

1. До редагування запущено `node --test tests/*.test.js`: **19 пройдено**.
2. Після редагування та сама команда: **19 пройдено**, без змін попередніх тестів.
3. Виконано `node tools/check_api_refactor.mjs`: **48 попарних порівнянь** старої та нової реалізації. Старий код завантажується з Git commit `bb273ec`, новий — із робочого файлу.
4. Окремо для обох реалізацій перевірено відкладене читання JSON: до завершення тіла `onBusy` має тільки true, після — true/false.

Порівнювалися результати, точні типи/тексти помилок, відправлені параметри й заголовки та послідовність завантаження. Набір охоплює 200/201/204, 400/401/403/404/405/429/500/503, некоректний JSON, Retry-After, offline, AbortError; кожний сценарій повторено зі стандартними й перевизначеними параметрами.

[Журнал до/після та порівняння](verification/pz24-refactor.txt). Скрипт порівняння використовує заглушку fetch; він не звертається до мережі й не записує дані. Для запуску потрібен Git-клон з доступним базовим commit, а не лише ZIP поточних файлів. Повний серверний набір не повторювався, оскільки серверний код, маршрути та схема БД не змінювалися. Браузерне приймання й незалежне review цими тестами не замінено.

## Результат та межі

Три обов’язки виділені в окремі функції, вкладені компактні блоки розгорнуті для читабельності, відповідальність за loading залишена в одному місці. Поведінка збігається на перевірених сценаріях. Прискорення або зниження споживання пам’яті не вимірювалися й не заявляються; мета — структура та підтримка коду.

BUG-005, BUG-006 і BUG-007 залишаються відкритими. Їх виправлення змінюватиме поведінку й має бути окремою роботою з повторним відтворенням. Попереднє виділення `input`, `area`, `select` до `form-fields.js` було ранньою підготовчою зміною; цей розділ описує новий завершений етап на актуальній версії, а не повторно зараховує давню зміну.
